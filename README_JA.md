# 📸 Obsidian Image Upload Toolkit

> Obsidian のノート内の画像を、複数のクラウドストレージへまとめてアップロードする

> **このリポジトリについて**
> [addozhang/obsidian-image-upload-toolkit](https://github.com/addozhang/obsidian-image-upload-toolkit) の
> [akikinyan によるフォーク](https://github.com/akikinyan/obsidian-image-upload-toolkit)です。

## 🚀 はじめに

### 5 分で使い始める

1. **プラグインを入れる**：BRAT で `akikinyan/obsidian-image-upload-toolkit` を追加する
2. **最低限の設定をする**：アップロード先に Imgur を選び、クライアント ID を入れる
3. **実行する**：任意のノートでコマンドパレットから「ページを公開」を実行する
4. **結果を確認する**：画像がアップロードされ、URL を差し替えた本文がクリップボードに入る

### 動作環境

- Obsidian 0.12.16 以降
- デスクトップのみ（Windows、macOS、Linux）
- モバイルは非対応

Node の API を直接使うため、モバイル版では動作しません。

## ✨ 機能

### 基本機能

- **画像の自動検出**：Markdown 形式と Wiki リンク形式の両方を認識する
- **対応形式**：PNG、JPG、JPEG、GIF、SVG、WebP、Excalidraw
- **一括アップロード**：ノート内の複数画像をまとめて処理する
- **進行状況の表示**：画像ごとの成否が分かるダイアログ（無効にするとステータスバー表示）
- **柔軟な保存パス**：相対パスと、日付やファイル名を埋め込む変数に対応する
- **外部画像の取り込み**：外部サイトを参照している画像を自分のストレージへ移す（任意）
- **Mermaid の画像化**：公開時に Mermaid のコードブロックを PNG に変換する（任意）
- **プロキシ対応**：S3 互換ストレージへの接続にプロキシを経由できる（このフォークの追加機能）
- **WebP 変換**：アップロード前にローカル画像を WebP に変換し、元ファイルの保管もできる（このフォークの追加機能、任意）
- **アップロード履歴**：内容が変わっていない画像を再アップロードしない（このフォークの追加機能）
- **日本語 UI**：Obsidian の言語設定に追従する（このフォークの追加機能）

### 対応ストレージ（10 種類）

| サービス | 向いている用途 |
|---|---|
| Imgur | 個人ブログ |
| GitHub | オープンソースのプロジェクト |
| Cloudflare R2 | 本格運用 |
| AWS S3 | 業務利用 |
| Aliyun OSS | 中国国内向け |
| TencentCloud COS | 中国国内向け |
| Qiniu Kodo | 中国国内向け |
| ImageKit | CDN による最適化 |
| Backblaze B2 | 保管コストの抑制 |
| Gyazo | 手早い共有 |

[GitHub Pages](https://pages.github.com) のような静的サイトへの公開や、外部ホストの画像 URL を必要とする場所への投稿に使えます。

## 🔨 インストールと設定

### 手順 1：プラグインを入れる

このフォークはコミュニティプラグインストアには登録されていません。
BRAT を使ってインストールします。

1. コミュニティプラグインから「BRAT」（Obsidian42 - BRAT）を入れて有効化する
2. BRAT の設定で「Add beta plugin」を選ぶ
3. `akikinyan/obsidian-image-upload-toolkit` を入力して追加する
4. 設定 → コミュニティプラグインで「Image Upload Toolkit」を有効化する

プラグイン ID は上流と同じなので、ストア版を入れている場合は同じフォルダが上書きされ、既存の設定（`data.json`）はそのまま引き継がれます。
BRAT は起動時に更新を確認するため、新しいリリースを出せば自動で配布されます。

### 手順 2：全体の設定

| 設定項目 | 推奨 | 効果 |
|---|---|---|
| 画像名を代替テキストにする | オン | リンクの角括弧内にファイル名が入る |
| 元のノートを書き換える | オフ | オフなら元のノートに手を触れず、結果をクリップボードに入れるだけ |
| プロパティを除いてコピーする | オン | コピーする本文からフロントマターを取り除く |
| 進行状況をダイアログで表示 | オン | 画像ごとの成否が分かる |
| 外部サイトの画像も取り込む | オフ | オンにすると参照先が消えても画像が残る |
| Mermaid 図を画像に変換する | オフ | Mermaid 非対応の場所へ貼るときにオンにする |
| Mermaid 画像の倍率 | 2 | 高解像度ディスプレイでの目安 |
| Mermaid のテーマ | デフォルト | ダーク、フォレスト、ニュートラル、ベースから選べる |
| 言語 | 自動 | Obsidian 本体の言語設定に従う |

WebP 変換とアップロード履歴は項目が多いため、[WebP 変換](#️-webp-変換)と[アップロード履歴](#️-アップロード履歴)で個別に説明します。

### 手順 3：アップロード先を選ぶ

「アップロード先のサービス」を選ぶと、その下の入力項目がそのサービス用のものに切り替わります。
サービスごとの設定は個別に保存されるので、切り替えても前の入力は消えません。
各サービスの設定値は[ストレージごとの設定](#-ストレージごとの設定)を参照してください。

## 📖 使い方

### 基本の流れ

1. ローカル画像を含むノートを開く
2. コマンドパレットを開く（Ctrl/Cmd + P）
3. 「ページを公開」を実行する
4. ローカル画像が設定したストレージへアップロードされる
5. URL を差し替えた Markdown がクリップボードに入る

![screenshot](https://github.com/user-attachments/assets/d20abcac-78a3-4275-b391-818ad781c219)

### 保存パスの変数

「保存先のパス」には次の変数が使えます。

| 変数 | 展開される値 |
|---|---|
| `{year}` | 年（4 桁） |
| `{mon}` | 月（2 桁） |
| `{day}` | 日（2 桁） |
| `{random}` | ランダムな 20 文字 |
| `{filename}` | 元のファイル名 |

`/{year}/{mon}/{day}/{filename}` を指定して `pic.jpg` をアップロードすると、`/2026/08/24/pic.jpg` に保存されます。
空欄にするとファイル名だけになるため、同名ファイルが上書きされる恐れがあります。

### そのほか

- **相対パス**：`./` と `../` で始まるパスを解決できます
- **添付ファイルフォルダ**：Obsidian の添付ファイル設定に従います
- **外部画像の取り込み**：設定でオンにすると、`http(s)://` を参照している画像もダウンロードして自分のストレージへ移します。すでに自分のストレージ上にある画像は対象外です

## 🔧 ストレージごとの設定

### 用途からの選び方

- **個人利用**：Imgur（無料で設定が最も簡単）
- **オープンソース**：GitHub（リポジトリでバージョン管理できる）
- **手早い共有**：Gyazo（トークン 1 つで済む）
- **本格運用**：Cloudflare R2（転送量課金がない）
- **業務利用**：AWS S3（CloudFront と組み合わせられる）
- **中国国内向け**：Aliyun OSS
- **コスト重視**：Backblaze B2（無料枠が大きい）

### Imgur

1. https://api.imgur.com/oauth2/addclient を開く
2. アプリケーションを作る（「OAuth 2 authorization without a callback URL」を選ぶ）
3. 発行されたクライアント ID をプラグインの設定に入れる

初期値はプラグイン共用のクライアント ID です。
アップロードが多いと回数制限に当たるため、自分の ID に差し替えてください。

### GitHub

1. `repo` スコープを付けたパーソナルアクセストークンを発行する
2. 画像を置くリポジトリを用意する（公開リポジトリなら外部から参照できる）
3. リポジトリを `owner/repo` の形式で、ブランチ名とトークンを設定する

画像は通常のファイルとしてコミットされます。

### Gyazo

1. https://gyazo.com/oauth/applications を開く
2. アプリケーションを作り、アクセストークンを発行する
3. アクセストークン、公開範囲、共通の説明文を設定する

OAuth のコールバックサーバーは不要で、発行したトークンを直接使います。
公開範囲を「自分のみ」にすると、ノートに貼った URL を他の人から開けなくなります。
共有するノートに貼るなら「全員」を選んでください。

### Cloudflare R2

1. Cloudflare のダッシュボードで R2 を有効化し、バケットを作る
2. R2 → 概要 → R2 API トークンの管理から、読み書き権限のトークンを発行する
3. 次の値を設定する

| 項目 | 値 |
|---|---|
| アクセスキー ID、シークレットアクセスキー | 発行したトークンの値 |
| エンドポイント | `https://<account-id>.r2.cloudflarestorage.com` |
| バケット名 | 作成したバケット |
| 公開に使うドメイン | `https://pub-xxxx.r2.dev` または割り当てた独自ドメイン |

R2 のエンドポイントは外部から直接参照できないため、「公開に使うドメイン」は実質必須です。

### AWS S3

1. 画像用の S3 バケットを作る
2. そのバケットへの `PutObject` 権限を持つ IAM ユーザーを作り、アクセスキーを発行する
3. 次の値を設定する

| 項目 | 値 |
|---|---|
| アクセスキー ID | `AKIA` で始まる 20 文字 |
| シークレットアクセスキー | 発行時にしか表示されない |
| リージョン | バケットのリージョン（例：`ap-northeast-1`） |
| バケット名 | 作成したバケット |
| 公開に使うドメイン | CloudFront を前に置く場合に指定する（任意） |

リージョンがバケットと一致していないとアップロードに失敗します。
バケットを直接公開せず CloudFront 経由で配信する場合は、「公開に使うドメイン」に CloudFront のドメインを入れます。

### Aliyun OSS

1. OSS バケットを作る
2. RAM コンソールで AccessKey のペアを発行する
3. アクセスキー ID、アクセスキーシークレット、リージョン（例：`oss-cn-hangzhou`）、バケット名を設定する

リージョンを選ぶとエンドポイントも自動で切り替わります。

### ImageKit

1. https://imagekit.io/registration/ でアカウントを作る
2. ダッシュボードで ImageKit ID、パブリックキー、プライベートキーを確認する
3. ImageKit ID とキーを設定する（保存先フォルダは任意）

ImageKit ID を入れるとエンドポイントは自動で設定されます。

### TencentCloud COS

1. COS バケットを作る
2. CAM コンソールで SecretId と SecretKey を発行する
3. シークレット ID、シークレットキー、リージョン（例：`ap-guangzhou`）、バケット名を設定する

### Qiniu Kodo

1. Kodo バケットを作る
2. アクセスキーとシークレットキーを発行する
3. アクセスキー、シークレットキー、バケット名、バケットに紐付けたドメインを設定する

Kodo は公開に使うドメインの設定が必須です。

### Backblaze B2

1. https://www.backblaze.com/b2/sign-up.html でアカウントを作り、バケットを作る
2. App Keys からアプリケーションキーを発行する
3. 次の値を設定する

| 項目 | 値 |
|---|---|
| アプリケーションキー ID | 発行された keyID |
| アプリケーションキー | 発行時にしか表示されない |
| リージョン | 例：`us-west-004`（バケット画面のエンドポイントに含まれる） |
| バケット名 | 作成したバケット |
| 公開に使うドメイン | CDN や独自ドメインを前に置く場合に指定する（任意） |

非公開バケットにするとリンクを開けません。

## 🖼️ WebP 変換

このフォークで追加した機能です。既定では無効になっています。

有効にすると、アップロードの前にローカル画像を WebP に変換し、ノートには WebP のリンクを書きます。
対象はローカル画像だけで、外部サイトから取り込む画像と Mermaid 図は変換しません。

### 設定項目

| 項目 | 既定値 | 内容 |
|---|---|---|
| 画像を WebP に変換する | オフ | 機能全体のオン・オフ |
| 変換する拡張子 | png, jpg, jpeg | カンマ区切り。ドットは不要 |
| 品質 | 80 | 下げるほど小さく、劣化も大きくなる |
| オリジナルも保存する | オフ | 無変換の元ファイルも保管用にアップロードする |
| オリジナルの保存先パス | /originals/{year}/{mon}/{day}/{filename} | 保管用の元ファイルを置く場所 |
| ノート単位で切り替えるプロパティ | webp | ノートのプロパティ名 |
| プロパティが無いときの既定 | オン | プロパティを書いていないノートに適用される |

### 変換されない場合

次のいずれかに当たる画像は、変換せずそのままアップロードします。
いずれも通知は出さず、開発者コンソールに記録するだけです。

- **変換後のほうが大きくなった場合**。小さい PNG では WebP のほうが大きくなることが珍しくありません。大きいほうを公開しては本末転倒なので、サイズを比べて元ファイルを選びます
- **辺の長さが 16384 ピクセルを超える場合**。canvas の上限です。勝手に縮小すると利用者が指示していない加工になるため、変換を見送ります
- **画像をデコードできない、あるいは WebP エンコーダが無い場合**

GIF と SVG を既定の拡張子から外しているのも同じ理由です。
変換は canvas を経由するため、アニメーション GIF は1コマ目だけになり、SVG はラスタライズされて拡大に耐えなくなります。
承知のうえで変換したい場合は、拡張子の欄に追加できます。

### オリジナルの保管

「オリジナルも保存する」をオンにすると、WebP に加えて無変換の元ファイルもアップロードします。
ノートに書かれるのは WebP のリンクのままで、元ファイルは保管用です。

保存先は「オリジナルの保存先パス」で指定します。
ただしパスを指定できるのは S3、Cloudflare R2、Backblaze B2、Aliyun OSS、Tencent COS、Qiniu Kodo だけです。
Imgur、Gyazo、ImageKit、GitHub では元ファイルが WebP と同じ場所に置かれますが、拡張子が違うので上書きは起きません。

元ファイルの保管に失敗しても、WebP のアップロードが済んでいれば公開は成功として扱います。
保管用のコピーのために、成功したアップロードを取り消す理由がないためです。

### 公開ダイアログの表示

「進行状況をダイアログで表示」を有効にしていると、その実行で何が効いているかがヘッダ右側にチップで出ます。

```
✓ アップロード中...        [WebP 品質 80] [履歴 有効]
```

WebP 変換を有効にしていても、そのノートがプロパティで対象外になっている場合は「WebP 変換 このノートは対象外」と表示します。
機能を切っている状態と見分けが付かないと、変換されない理由を設定画面まで探しに行くことになるためです。

**進行中**は進捗バーと件数が出ます。
**完了すると、その場所がサイズ比較バーに置き換わります。**
100% の進捗バーは何も語らないので、同じ場所で変換の結果を示すようにしています。

```
✓ 完了                     [WebP 品質 80] [履歴 有効]

変換後 1000 B                                削減 2.9 KB
[▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░]
元 3.9 KB（-75%）
成功 3 件 · 履歴から 1 件
```

バー全体が元のサイズです。
灰色の部分がアップロードする分、**右端の緑が削減できた分**で、緑が長いほど圧縮が効いています。

画像ごとの行には、右端に結果が付きます。
変換した行には縮小率を表す小さなバーも付くので、枚数が多いときにどれがよく縮んだかが一目で分かります。
画像が1枚だけのときは、上の比較ブロックが同じことを言っているので行の数値は省きます。

| 表示 | 意味 |
|---|---|
| ▁▁▁░░ 1.2 MB → 340 KB | 変換した。バーの塗り幅が変換後の割合 |
| 2 KB | 変換していない。アップロードしたサイズ |
| 履歴から再利用 | アップロードしていない。記録した URL を使った |

比較バーと合計に含まれるのは、その実行で実際に変換した画像だけです。
履歴から再利用した画像は変換していないので、サイズの変化を表示しません。測っていない数字を出さないためです。

### ダイアログが閉じるまで

全件成功した場合、5 秒後に自動で閉じます。
残り時間は下端の細いバーで示します。
**ダイアログにマウスを乗せているあいだはカウントダウンが止まり**、離すと残り時間から再開します。
数字を読んでいる最中に消えないようにするためです。

失敗が1件でもある場合は自動で閉じません。

### ノート単位での切り替え

特定のノートだけ変換したくない場合は、そのノートのプロパティに次のように書きます。

```yaml
---
webp: false
---
```

プロパティ名は設定で変えられます。
`true` なら変換し、`false` なら変換しません。
プロパティを書いていないノートには「プロパティが無いときの既定」が適用されます。

この既定をオフにすると、逆の運用になります。
つまり全体としては変換せず、`webp: true` と書いたノートだけを変換します。

## 🗂️ アップロード履歴

このフォークで追加した機能です。既定で有効です。

これまでは「ページを公開」を実行するたびに、ローカル画像を毎回読み直して再アップロードしていました。
保存パスが日付とファイル名だけなら同じ場所を上書きするので実害は見えにくいのですが、`{random}` を含めているとゴミが増え続けます。
WebP 変換を有効にすると、変換の処理時間と通信量が二重にかかることにもなります。

有効にしておくと、アップロードしたファイルの内容と、その結果の URL を記録します。
次回以降、内容が変わっていない画像は記録した URL を使い回し、アップロードを省きます。
画像を編集すれば内容が変わるので、自動的にアップロードし直されます。

記録はバケットやリージョン、独自ドメインの組み合わせごとに分かれています。
アップロード先を別のバケットに変えたときに、古いバケットの URL が返ることはありません。

### 保存先と同期

記録はプラグインフォルダの `upload-cache.json` に保存されます。
`data.json` には入らないので、設定ファイルが肥大化することはありません。
上限は 5000 件で、古いものから捨てられます。

**このファイルは Vault の同期対象から外すことをお勧めします。**
内容に認証情報は含まないので同期しても危険ではありませんが、公開のたびにファイル全体が書き換わるため、コミットを重ねるほど Git の履歴が膨らみます。
1件あたり約 260 バイトなので、画像 500 枚で約 130KB、上限まで溜まると約 1.3MB です。

Git で同期している場合は、プラグインフォルダに `.gitignore` を置いてください。

```gitignore
upload-cache.json
```

同期しないと PC ごとに別の履歴になります。
別の PC で初めて公開したときだけ全画像がアップロードされ、以降はその PC でも省かれます。

### 履歴の消去

設定 → アップロード履歴 → 「アップロード履歴を消去」で記録をすべて破棄できます。
次回の実行で全画像をアップロードし直します。
アップロード済みのファイル自体は削除されません。

ノートのリンク先が開けなくなったとき（アップロード先のファイルを消した、バケットを作り直した、など）に使ってください。

## 🔒 プロキシ配下での利用

このフォークで追加した機能です。

10 種類のうち 7 種類は Obsidian の `requestUrl` を通して通信するため、OS のプロキシ設定に従います。
**Amazon S3、Cloudflare R2、Backblaze B2 の 3 つだけは AWS SDK が Node の `https` モジュールで直接通信します。**
Node は `HTTPS_PROXY` などの環境変数も OS のプロキシ設定も参照しないため、この 3 つは社内プロキシ配下では接続できません。
症状は接続のタイムアウトで、認証情報の誤りと見分けが付きにくいところが厄介です。

設定 → Image Upload Toolkit → ネットワーク → プロキシで動作を選べます。

| 選択肢 | 動作 |
|---|---|
| 環境変数から自動で使う（既定） | `HTTPS_PROXY` と `HTTP_PROXY` を読み、`NO_PROXY` の除外指定も反映する |
| プロキシを使わない | 環境変数が設定されていても直接接続する |
| URL を手入力する | 指定した URL を使い、環境変数は無視する |

手入力の書式は `http://proxy.example.com:8080` です。
認証が必要なプロキシなら `http://ユーザー名:パスワード@proxy.example.com:8080` と書きます。

この節には実際に使われるプロキシが表示されます（認証情報は隠されます）。
開発者コンソールを開かずに設定を確かめられます。

`NO_PROXY` の照合規則は curl と同じで、`example.com` と書いた場合はそのホスト名との完全一致だけが除外されます。
サブドメインまで除外するには `.example.com` または `*.example.com` と書いてください。

TLS を終端して中身を検査する種類のプロキシを使う場合は、その認証局の証明書を Node の信頼ストアに入れる必要があります（`NODE_EXTRA_CA_CERTS`）。
これはプラグインの側では対処できません。

## 🔒 プライバシーと通信

このプラグインが外部へ通信するのは、設定で選んだアップロード先に対してだけです。
利用統計や解析のための送信は一切ありません。
通信は Obsidian の `requestUrl` か、S3 互換サービス向けの公式 AWS SDK を通して行われます。

### 接続先

設定したサービスに応じて、次のホストのいずれかに接続します。
設定していないサービスのエンドポイントには接続しません。

| サービス | 接続先 |
|---|---|
| Imgur | `api.imgur.com` |
| Gyazo | `upload.gyazo.com` |
| Aliyun OSS | `<bucket>.<region>.aliyuncs.com` |
| ImageKit | `upload.imagekit.io` |
| AWS S3 | `s3.<region>.amazonaws.com` |
| Tencent COS | `<bucket>.cos.<region>.myqcloud.com` |
| Qiniu Kodo | `upload.qiniup.com` |
| GitHub | `api.github.com` |
| Cloudflare R2 | `<account-id>.r2.cloudflarestorage.com` |
| Backblaze B2 | `s3.<region>.backblazeb2.com` |

プロキシを有効にしている場合、S3、R2、B2 への通信は指定したプロキシを経由します。

### 追加の通信が発生する任意機能

- **外部サイトの画像も取り込む**（既定でオフ）：オンにすると、ノート内の `http(s)://` の URL から画像をダウンロードします。接続先はその URL のホストです
- **Mermaid 図を画像に変換する**（既定でオフ）：描画は Obsidian 内で完結し、描画のための通信は発生しません。生成された PNG は通常の画像と同じようにアップロードされます

### 認証情報の扱い

- 入力した API キーやトークンは、端末上の `.obsidian/plugins/image-upload-toolkit/data.json` にのみ保存されます
- 認証情報は、対応するサービスの公式エンドポイントに対してだけ、そのサービスが要求する署名方式で送られます
- アップロードする画像を除き、ノートの内容が外部へ送られることはありません

`data.json` は平文です。
Vault を Git やクラウドストレージで同期している場合は、このファイルを同期対象から外してください。

## 🔍 トラブルシューティング

### 画像が見つからないというエラーが出る

Obsidian の添付ファイルフォルダの設定と、実際の画像の位置がずれている場合に起こります。
添付ファイル設定を確認し、指定したパスに画像が存在するか確かめてください。
切り分けのために絶対パスで試すのも有効です。

### アップロードがタイムアウトする

プロキシ配下で S3、Cloudflare R2、Backblaze B2 を使っている場合、[プロキシ配下での利用](#-プロキシ配下での利用)を設定していないとこうなります。
設定 → ネットワークでプロキシの検出状況を確認してください。

### Imgur のアップロードが失敗する

クライアント ID の誤りか、回数制限です。
Imgur には利用制限があるため、数分待って再試行してください。
頻繁に当たる場合は自分のクライアント ID を発行するか、別のサービスに移ることを検討してください。

### 相対パスが解決されない

`./` または `../` で始まる形式を使い、Obsidian の添付ファイル設定を確認してください。

### 進行状況のダイアログが出ない

「進行状況をダイアログで表示」がオンになっているか確認し、Obsidian を再起動してください。
それでも出ない場合は、他のプラグインとの競合が疑われます。

### ファイル名に空白や記号が含まれる画像のリンクが壊れる

1.7.0 で修正済みです。
Obsidian が貼り付けた画像に付ける `Pasted image 20260824080301.png` のような名前は空白を含み、URL に空白がそのまま入るとリンクが途中で切れていました。
1.7.0 以降は `Pasted%20image%2020260824080301.png` のようにパーセントエンコードされます。

### 外部画像のダウンロードが失敗する

参照先が到達不能か、認証を要求している場合に起こります。
認証が必要な画像はダウンロードできません。
ローカル画像だけを扱いたい場合は「外部サイトの画像も取り込む」をオフにしてください。

## 📈 運用のこつ

### 進め方

アップロード前にノートをバックアップし、まずテスト用の画像 1 枚で設定を確かめてから本番のノートに適用してください。
アップロードした URL は、公開先から実際に開けるか確認しておくと安全です。

### 認証情報の管理

API キーを公開しないこと、定期的に更新すること、必要最小限の権限だけを与えることの 3 点を守ってください。
S3 なら、対象バケットへの `PutObject` だけを許可した IAM ユーザーで十分です。

### ファイルの整理

保存パスの変数を使って日付やプロジェクトごとに自動で振り分けると、後から探しやすくなります。
`{filename}` だけの構成は同名ファイルの上書きを招くため避けてください。
